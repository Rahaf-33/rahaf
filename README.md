# بصمة رقمية — منصة ورشة معلمات الحاسب

> إبداع تقني يبدأ بفكرة، ويترك أثرًا في الممارسة.

منصة ويب عربية (RTL) برابط واحد ورمز QR واحد، فيها:

| الصفحة | الرابط | الوظيفة |
|---|---|---|
| الرئيسية | `/` | الترحيب، والمساران، وأحدث المشاركات (تتحدث مباشرة) |
| المسار الأول | `/tracks/interactive` | إدارة الحصة التفاعلية: الحصة الافتراضية، والأدوات الثمانية، ومثال «الأمن السيبراني»، ومساحة التطبيق |
| المسار الثاني | `/tracks/assessment` | التقويم من أجل التعلم: المفاهيم، والاستراتيجيات الخمس، وأمثلة البرمجة وتصميم الواجهات، والطرق الحديثة، ومساحة التطبيق |
| رفع مشاركة | `/submit` | نموذج موحد مهيأ للجوال، مع رفع حتى 3 ملفات (صور، PDF، PowerPoint، Word، Excel، MP4) بحد 15MB للملف، ورابط خارجي |
| المعرض | `/gallery` | «إبداعات معلماتنا»: تصفية حسب المسار وبحث، ويتحدث لحظيًا |
| تفاصيل مشاركة | `/gallery/[id]` | الصور والملفات والرابط |
| وضع العرض | `/present` | للسبورة: مشاركة واحدة في كل شاشة، وأزرار التالية/السابقة، وملء الشاشة، وتنبيه بالمشاركات الجديدة |
| رمز QR | `/qr` | رمز للرابط المنشور، وتحميل بطاقة PNG جاهزة للعرض |
| الختام | `/closing` | «كل بصمة تصنع فرقًا»، وأرقام حقيقية تتحدث مباشرة |
| الإدارة | `/admin` | للمدربة: إخفاء المشاركات أو إظهارها أو حذفها (بكلمة مرور) |

**اختصارات وضع العرض:** ← التالية · → السابقة · `F` ملء الشاشة · `Q` إظهار رمز QR · السحب باللمس على السبورة الذكية.

## التقنيات
Next.js 15 (App Router) + TypeScript + Tailwind CSS + Supabase (Postgres وStorage وRealtime).

### كيف تعمل البيانات
- **القراءة:** عبر `/api/submissions` في الخادم، وتُعاد فقط المشاركات الظاهرة.
- **الرفع:** يطلب المتصفح رابط رفع موقّعًا من `/api/uploads` بعد التحقق من نوع الملف وحجمه، ثم يرفع الملف **مباشرة** إلى Supabase Storage، فلا يمر الملف عبر Vercel ولا يتأثر بحد حجم الطلبات. تُصغَّر صور الجوال الكبيرة تلقائيًا قبل الرفع.
- **الحفظ:** `/api/submissions` (POST) يتحقق من الحقول ومن وجود الملفات فعلًا، ثم يحفظ المشاركة بمفتاح `service_role` في الخادم فقط.
- **التحديث اللحظي:** Supabase Realtime على جدول `submissions`. وللاحتياط، إذا حجبت شبكة المدرسة WebSocket، يعاد الجلب تلقائيًا كل 12 ثانية وعند الرجوع إلى التبويب.
- **الأمان:** سياسات RLS تسمح للعامة **بالقراءة فقط** للمشاركات غير المخفية. لا توجد صلاحية إضافة أو تعديل أو حذف بالمفتاح العام، والحاوية لا تقبل الرفع إلا بروابط موقّعة. الإدارة محمية بكلمة مرور وكوكي `httpOnly`.
- **لا يُستخدم localStorage للحفظ.** يُستخدم فقط لتذكّر اسم المعلمة على جوالها من باب التسهيل.

## الإعداد (مرة واحدة، نحو 10 دقائق)

### 1) إنشاء مشروع Supabase
1. أنشئي حسابًا مجانيًا في <https://supabase.com>، ثم **New project**.
2. من **SQL Editor** الصقي محتوى الملف
   `supabase/migrations/20261125000000_basmah_platform.sql` واضغطي **Run**.
   ينشئ هذا الملف جدولَي `tracks` و`submissions`، وسياسات RLS، ويفعّل Realtime، وينشئ حاوية التخزين `submissions`. يمكن تشغيله أكثر من مرة دون ضرر.
3. من **Project Settings › API** انسخي: Project URL، والمفتاح `anon` (أو publishable)، والمفتاح `service_role` (أو secret).

### 2) التشغيل المحلي
```bash
npm install
cp .env.example .env.local   # ثم املئي القيم
npm run dev                  # http://localhost:3000
```

| المتغير | أين يُستخدم | ملاحظة |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | المتصفح والخادم | رابط المشروع |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | المتصفح | عام وآمن (مقيد بسياسات RLS) |
| `SUPABASE_SERVICE_ROLE_KEY` | **الخادم فقط** | سري، لا تضعيه أبدًا بمتغير يبدأ بـ `NEXT_PUBLIC` |
| `ADMIN_PASSWORD` | الخادم | كلمة مرور صفحة `/admin` |
| `NEXT_PUBLIC_SITE_URL` | رمز QR | اختياري؛ الرابط المنشور، مثل `https://basmah.vercel.app` |

> للتطوير دون حساب سحابي يمكن تشغيل Supabase محليًا (يتطلب Docker): `npx supabase start`، ثم استخدام المفاتيح التي يطبعها.

### 3) النشر على Vercel
1. ارفعي المستودع إلى GitHub، ثم من <https://vercel.com/new> استورديه (يكتشف Vercel أنه مشروع Next.js تلقائيًا).
2. أضيفي متغيرات البيئة الخمسة في **Settings › Environment Variables**.
3. اضغطي **Deploy**، ثم افتحي `https://<رابطك>/qr` وحمّلي بطاقة رمز QR.
4. إذا أضفتِ `NEXT_PUBLIC_SITE_URL` بعد أول نشر، أعيدي النشر (Redeploy) لأن المتغيرات العامة تُضمَّن وقت البناء.

## سير الورشة المقترح
1. **قبل البداية:** اعرضي `/qr` (أو اضغطي `Q` في وضع العرض) لتدخل المعلمات من جوالاتهن.
2. **الموضوع الأول:** اشرحي من `/tracks/interactive`، ثم تطبق المعلمات وترفعن أعمالهن من «أضيفي مشاركتك».
3. **العرض:** افتحي `/present?track=interactive` واضغطي `F`، ثم استعرضي الأعمال واحدة تلو الأخرى. تصل المشاركات الجديدة تلقائيًا مع تنبيه.
4. **الموضوع الثاني:** كرري الخطوات نفسها مع `/tracks/assessment`.
5. **الختام:** افتحي `/closing` لعرض الأرقام الحقيقية. تبقى المكتبة في `/gallery` متاحة بعد الورشة.

## الاختبار الذي أُجري
اختُبرت المنصة على Supabase حقيقي يعمل محليًا (Postgres وStorage وRealtime) باستخدام Playwright:
- جوالان (iPhone 13 وPixel 7) يرسلان مشاركتين **في الوقت نفسه**، إحداهما بصورة ورابط والأخرى بملف PDF، ونجح الإرسال في الحالتين.
- ظهرت المشاركات في المعرض المفتوح على جهاز المدربة خلال أقل من ثانية **دون تحديث الصفحة**، وفي وضع العرض مع تنبيه «مشاركة جديدة».
- عملت أزرار التالية والسابقة واختصارات لوحة المفاتيح، والانتقال إلى المشاركة الجديدة من التنبيه.
- ظهرت أرقام الختام صحيحة ومستمدة من البيانات المحفوظة.
- الإدارة: رُفضت كلمة المرور الخاطئة، واختفت المشاركة المخفية من المعرض تلقائيًا، وأُغلق API الإدارة أمام غير المسجلات.
- رُفض الإدخال المباشر بالمفتاح العام (RLS)، ورُفض الرفع المباشر إلى التخزين، ورُفضت الملفات غير المدعومة أو الكبيرة.
- لا يوجد تمرير أفقي على الجوال في أي صفحة.
